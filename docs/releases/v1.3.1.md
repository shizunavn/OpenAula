# OpenAula v1.3.1

Fixes for the WIN 68 HE MAX RGB editor after 1.3.0.

## Rhythm Sync and Custom RGB start on WIN 68 HE MAX

Both editors handed the board to the HERO68 WebHID manager whenever the
background app reported `connected`. That handoff sends HERO68's `0x82`
identity probe, which a WIN 68 HE MAX never answers, so starting Rhythm Sync or
Custom RGB failed with `Error: unsupported`. The handoff now only happens for
HERO68 / HERO84.

## Custom RGB survives tab changes

The sidebar and the RGB page tracked the active RGB tab separately. Switching
tabs from the sidebar left the page on the previous editor, so the Custom
editor was hidden and its preview engine released while the shell still
expected its output; coming back showed an all-black preview. The page now
follows the shell's tab and publishes its own back.

## Custom Effects

- The seven gradient palettes are always shown. Before, the palette row
  disappeared as soon as a gradient layer was switched to a single color.
- The base effect picker lists the base effects the other board has and this
  one does not, so a missing onboard effect is visible instead of silently
  absent. Per-key modes stay out, they are tied to one key map.
- The "Merge preset" button, which imported exported JSON profiles, is removed.

## WIN 68 HE MAX onboard colors

Selecting Multicolor in the onboard color strip reset the draft to the
multicolor color instead of writing `colorIndex 0` together with a leftover
single color into the firmware's first palette slot, which turned the LEDs off.

## Saving key settings

Saving actuation / Rapid Trigger settings on WIN 68 HE MAX no longer fails with
`Key setting readback mismatch`. The `0x23` table that came back is an echo of
the write that carried it, and a key the firmware skips is missing rather than
wrong.

## Validation

670 JavaScript tests pass, the web build passes and both TypeScript projects
typecheck. Nothing in this release was validated on a physical WIN 68 HE MAX
from this repository.
