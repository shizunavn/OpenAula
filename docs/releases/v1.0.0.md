# OpenAula v1.0.0

The first stable release. The app and the Windows service now share one version
number instead of drifting apart (UI 0.9.59 and service 0.6.1 were the last
independent pair).

## New name, and what it means for an existing install

The project is called **OpenAula** from this release on, and the technical
identifiers moved with it: the GitHub repository, `%LOCALAPPDATA%\OpenAula`, the
`OpenAula.exe` launcher, the `OpenAulaService.exe` core, the uninstall entry, the
autostart value and the release asset names.

Setup takes over a pre-1.0 install rather than installing beside it:

- if the old `OpenHero68` copy is present, setup removes it first (a new AppId
  means Inno would otherwise leave both running and fighting for the service
  port);
- your auto-start choice carries over from the old registry value;
- settings, profiles, logs and saved presets are copied from
  `%LOCALAPPDATA%\OpenHero68\rgb-service` on first start and the old folder is
  removed once the copy succeeds;
- the pre-1.0 environment variables (`OPENHERO68_*`) are still read, so an old
  launcher that starts a new core keeps working.

If the old copy cannot be removed automatically, setup stops and says so instead
of leaving two tray apps behind.

## Everything inherited from 0.9.59 / service 0.6.1

- HERO68 and HERO84 selection from the device UUID, with the 84-key layout,
  key table and colour mirroring for the extra keys.
- HERO84 key table verified against the official AULA driver
  (`docs/hero84-verification.md` lists what is proven and what still needs a
  physical board).
- Custom Effects, Rhythm Sync and Gamepad, the Windows background service with
  signed updates, and the static Cloudflare Pages build.

## Validation

624 JavaScript tests pass, and the web and service TypeScript builds pass.

The HERO84 path is still not validated on a physical board: the 212-byte CMD08
frame, the mirrored colours for the extra keys and any HERO84-specific firmware
behaviour remain unverified. The upgrade path from 0.9.59 was verified by the
installer smoke test, not against a real 0.9.59 installation.
