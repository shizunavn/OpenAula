# OpenAula v1.9.1

Internal code organisation plus one fix to how a failed update reports itself. Your saved profiles, RGB presets, macros and share codes keep working.

## Web app

- No visible changes. Same layout, same controls, same behaviour.

## Windows tray service

- **Update failures now always report a reason.** When an automatic update rolled back, the status briefly showed the failure phase with no explanation, then filled in the message a moment later. Anything reading the status in that gap saw an empty error. The reason is now written in the same step as the `failed` phase, so the first failure status you see already explains itself. Rollback behaviour is unchanged.

## Fixes

- `executeTransaction` called `phase('failed')` and then `actions.phase('failed', message)` — two writes, the first without an error. It is now a single `phase('failed', message)` call, and `phase()` forwards the optional error.

## Under the hood

- **Editing pages split into focused modules**, so each file has one job:
  - `AdvancedKeysPage` → `advanced-keys/`: `AdvancedKeysOverview`, `AdvancedKeyEditorPanel`, `AdvancedKeySidePanel`, `AdvancedKeyModals`, `advancedKeysMeta`. This page no longer touches the device managers directly; it goes through the protocol driver.
  - `CustomRgbEditor` → `custom-rgb/`: toolbar, layer stack, layer parameters, base parameters, colour controls, effect selector, preview section, service details.
  - `MacroPage` → `macro/`: library sidebar, event sequence, playback footer, discard modal.
  - `RgbSettingsPage` → `rgb/`: effect library panel, parameters card, paused view, saved presets section.
- **`useDeviceSyncController` got smaller** as the page-level read/write paths moved behind the protocol driver instead of calling the device managers directly.
- Remaining direct `hero68DeviceManager` / `xsydDeviceManager` access from `CustomRgbEditor`, `MacroPage` and `RgbSettingsPage` was left as-is.
