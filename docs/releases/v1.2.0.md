# OpenAula v1.2.0

Adds the AULA WIN 68 HE MAX as a supported board, on its own protocol stack.
Everything already supported for HERO68 and HERO84 stays unchanged.

## WIN 68 HE MAX

The board speaks XSYD `0x5C`, not the HERO68 `0x09` command set, so it is
detected separately and never sent a HERO68 frame.

- **Per-key settings** go through the `0x23` field table: remap, actuation
  point, rapid trigger, dead zone and switch type. Travel is in micrometres
  (`1500` = 1.50 mm), which is 100× the unit the HERO68 code uses, so the two
  paths deliberately do not share a converter.
- **Advanced keys**: Mod-Tap (`0x24`), Toggle (`0x25`), Multi-Point Trigger
  (`0x27`) and Release Action (`0x28`) read, edit and save, with each frame
  compared byte for byte against a USB capture of the official web driver.
- **Polling rate** is read and written over `0x00` subcommand `0x50` and
  followed by a USB re-enumeration wait. The sequence matches a
  4000 → 2000 → 1000 Hz capture from the official driver.

## What is deliberately blocked

A frame layout that has not been proven by capture is not guessed:

- **DKS** opens an explicit "not supported on WIN 68 HE MAX" modal instead of
  opening the editor, and saving a profile that contains DKS is refused.
- **Rappy Snappy**, **DDKS** and **SOCD priority modes other than the default**
  are disabled in the UI until a capture shows their layout.

If you need one of these, capture it with USBPcap while changing it in the
official driver and open an issue with the `.pcapng` file.

## Validation

665 JavaScript tests pass, the web build passes, and both the web and service
TypeScript projects typecheck. HERO68 and HERO84 behaviour is covered by the
existing suite.

The WIN 68 HE MAX frames are checked against USBPcap captures, not against new
hardware runs from this repository: the write path for polling rate and the
Hall 30-channel map are verified by capture replay only. DKS, RS, DDKS and
non-default SOCD modes are untested because no capture exists for them.

## Windows setup

Version 1.2.0 covers the app and the service together. The installer and the
signed update manifest are built by the Windows setup workflow; the upgrade
path is checked by the installer smoke test, not against a real installation.
