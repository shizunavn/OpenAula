# OpenAula v1.2.1

Two fixes and the WIN 68 HE MAX Hall stream.

## Hall stream on WIN 68 HE MAX

The Windows service now reads analogue travel and pressed state from the
board on the `0x12` request / `0x92` reply pair, so Rhythm Sync and the live
Hall test work on it. Travel is a 63-entry `u16` table in micrometres, polled
twice because the 126 matrix positions do not fit in one reply; pressed state
is one byte per matrix position. Both were checked against
`travel_test_press_randomkey.pcapng`.

The 126 matrix positions are mapped onto the 68 physical keys by an explicit
table, so a key the firmware reports but the app cannot place is dropped
instead of being shown on the wrong key.

## WIN 68 HE MAX replies no longer fail on a stale frame

A reply that belonged to an earlier request used to be matched against the
request that was waiting, which surfaced as `Unexpected XSYD reply opcode
0x80 (expected 0xa3)`. Replies are now matched on their own opcode; anything
else is discarded and the waiting request keeps its timeout. Frames that make
the board re-enumerate, such as a polling-rate change, no longer wait for a
reply that never comes.

## Advanced Keys: RS and DDKS

The greyed-out Rappy Snappy and DDKS cards are gone from the WIN 68 HE MAX
Advanced Keys page. No capture exists for either layout, so there is nothing
to show; DKS still opens the explicit unsupported dialog.

## Keyboard preview at 2560x1440

At a narrow preview the layout used to shrink below its key widths. The case
now measures its own layout width and never renders narrower than the keys it
holds.

## Validation

666 JavaScript tests pass, the web build passes, both TypeScript projects
typecheck, and the native Hall/gamepad checks pass. The Hall stream is verified
by replaying the capture, not against a physical board from this repository.
