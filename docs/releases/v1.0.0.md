# OpenAula v1.0.0

The first stable release. The app and the Windows service now share one version
number instead of drifting apart (UI 0.9.59 and service 0.6.1 were the last
independent pair).

## New name

The app is called **OpenAula** from this release on, because it covers the AULA
line (HERO68, HERO84) rather than a single board. Nothing you already installed
moves: settings, profiles, the install folder, the background service and the
update feed keep the same locations and names as before, so an update from
0.9.59 installs straight over it and keeps every saved setting.

## What changed in the code

- Product identity now lives in one file per side (`src/brand.ts` and
  `service/brand.ts`), so a future rename is one edit plus one migration instead
  of a search across the codebase. Display name and technical identifiers are
  separate on purpose: the identifiers are contracts with copies already
  installed.
- The update feed, release asset names, autostart value, uninstall key and
  settings directory are unchanged.

## Everything inherited from 0.9.59 / service 0.6.1

- HERO68 and HERO84 selection from the device UUID, with the 84-key layout,
  key table and colour mirroring for the extra keys.
- HERO84 key table verified against the official AULA driver
  (`docs/hero84-verification.md` lists what is proven and what still needs a
  physical board).
- Custom Effects, Rhythm Sync and Gamepad, the Windows background service with
  signed updates, and the static Cloudflare Pages build.

## Validation

624 JavaScript tests pass, and the web and service TypeScript builds pass.

The HERO84 path is still not validated on a physical board: the 212-byte CMD08
frame, the mirrored colours for the extra keys and any HERO84-specific firmware
behaviour remain unverified.

Install the complete Windows setup to update the native app.
