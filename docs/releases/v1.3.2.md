# OpenAula v1.3.2

Rhythm Sync and Hall polling on the WIN 68 HE MAX.

## Rhythm Sync runs in the service

Rhythm Sync on WIN 68 HE MAX no longer needs the RGB tab open. The background
service already captures audio and renders the same 68-key frame the HERO68
boards use; it now also encodes that frame for XSYD:

- `0x18` with mode `0x15` (Per-key Color) at full brightness, written once when
  a session starts and before the first colour batch.
- `0x2A` batch writes of 14 keys each, so five reports per changed frame. A frame
  whose colours did not change sends nothing.
- `rhythm-stop` writes `0x18` with mode `0x00` (Static), so the board returns to
  its onboard effect instead of freezing on the last rhythm frame.

The key order and the `usage & 0xff` key values are pinned by
`tests/rhythm-xsyd-service.test.mjs`.

## Hall polling holds its demand

A WIN 68 HE MAX Hall cycle answers travel and pressed state as two separate
replies of three 64-byte reports each, which is two writes and six blocking
reads per cycle. With the old 100 ms budgets, one slow reply stalled the next
deadline; a miss then closed the HID handle and paid a 250-2000 ms backoff, so a
demanded 200 Hz measured around 70-80 Hz.

- A round trip now allows 10 ms for the write and 15 ms for the reply.
- A read miss costs the cycle, not the device. The handle is no longer closed on
  a timeout, travel and pressed are accepted independently, and a missed pressed
  reply reuses the last good one rather than reporting every key released.
- A failed write still drops the handle.

## Smaller fix

Writing a HERO68 `0x09` lighting frame to an XSYD board now reports an error;
before, the write was accepted and silently dropped.

## Validation

676 JavaScript tests pass, the service builds with MSVC, and both TypeScript
projects typecheck. Nothing in this release was validated on a physical
WIN 68 HE MAX from this repository: the six reports per Hall cycle have not been
timed, so read the real rate back from `hall-stats` (per-key measured Hz and
lifetime p99) before trusting the 200 Hz demand.
