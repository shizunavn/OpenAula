# OpenAula v1.9.0

Internal restructuring of how keyboard models and protocols are described. **No changes to how you use the web app or the tray service** — your saved profiles, settings and share codes keep working.

## Web app

- No visible UI changes. The layout, pages and controls are the same as v1.8.1.
- One behaviour fix: the **"Read RGB from this profile before saving"** guard on non-XSYD boards never triggered because of an inverted comparison, so a save could go through without the RGB values being read back first. It now blocks the save as intended.

## Windows tray service

- No functional changes to Custom RGB, Rhythm Sync, Auto-Profile Switching or Gamepad output.
- **Startup RGB restore**: the service now stops the RGB engine without rewriting the saved state when it shuts down, and re-applies your custom or Rhythm RGB on the next start when it comes up offline (for example with the keyboard unplugged). Previously that state could be lost until you re-saved it from the web app.

## Fixes

- **WIN 68 HE MAX — Smart Slot 3 auto-switching** could fail during warm-up because the profile Hall signature was built from a key table that no longer existed. The signature is now derived from the target board's key list, so the zero-wear game-profile switch works again.
- **RGB read-back guard** (see Web app above).

## Under the hood

- **Board registry is now the single source of truth.** Each board declares its protocol, key IDs, precision/limits, switches, RGB, profile slots, advanced keys and device settings once. The service hardware executor reads `keyIds` and `distanceUnitMm` from the board instead of hardcoded per-model tables (`HERO68_KEY_IDS`, `HERO84_KEY_IDS`, precision literals), and XSYD detection keys off `board.protocol` rather than a model-ID comparison.
- **Protocol modules split for readability.** `src/protocol/xsyd/device.ts` (~1900 lines) is now a small barrel over `commands`, `advancedBindings`, `remap`, `hydrate`, `webhid`, `hall`, `rgb`, `features`, `codec`, `keymap` and `advanced`. An import cycle between `hydrate` and `advancedBindings` is gone.
- **New protocol driver layer** (`src/protocol/driver.ts`) with `bytetechDriver` / `xsydDriver` and `getProtocolDriver`, `getActiveConnectedDriver`, `isAnyProtocolConnected`, `disconnectAllProtocols`, `autoConnectAnyProtocol`. Device connect, hydrate, profile-slot read and disconnect now go through it.
- **Frontend components split** into `advanced-keys/`, `custom-rgb/`, `macro/` and `rgb/` modules, plus a new `useSlotHistory` hook with per-slot undo/redo.
- **Native HID helpers extracted** from `hid_bridge.cpp` into `hid_device_catalog.h`, `hid_packet_policy.h` and `hid_ipc_router.h` (raw-input filtering and VID/PID catalogs, packet validation and command allowlists, IPC queueing).
