# OpenAula v1.9.0

Codebase-wide refactor: board registry as the single source of truth, split protocol modules, a protocol driver abstraction, and native HID helpers extracted from the bridge.

## Board Registry as Single Source of Truth

- **Typed board descriptors** (`src/keyboard/registry/types.ts`, `shared/presets.ts`, `shared/bytetechCatalog.ts`):
  - Boards now declare `protocol`, `keyIds`, `performance` (`distanceUnitMm`, Hall units, actuation/RT limits), `switches`, `rgb`, `profiles`, `advancedKeys`, and `deviceSettings` in one place.
  - Shared specs (`BYTETECH_DEFAULT_SPECS`, `XSYD_DEFAULT_SPECS`) remove duplicated per-board constants.
  - `HERO68`, `HERO84`, and `WIN 68 HE MAX` board files now only declare what differs.
- **Consumers migrated off hardcoded tables**:
  - `service/profile/hardwareExecutor.ts` uses `getBoard(model).keyIds` and `board.performance.distanceUnitMm` instead of `HERO68_KEY_IDS` / `HERO84_KEY_IDS` and per-model precision literals.
  - XSYD detection now keys off `board.protocol === 'xsyd'` rather than a model-id comparison.
  - `HERO_DEVICE_MODELS` filters to ByteTech boards; `ALL_DEVICE_MODELS` is derived from the registry.

## XSYD Protocol Module Split

- `src/protocol/xsyd/device.ts` (previously ~1900 lines) is now a barrel over focused modules: `commands`, `advancedBindings`, `remap`, `hydrate`, `webhid`, `hall`, `rgb`, `features`, `codec`, `keymap`, `advanced`.
- Shared `requireXsydKeyValue` moved to `features.ts` so `hydrate` and `advancedBindings` no longer form an import cycle.
- The per-slot written-field cache moved into `remap.ts` where the encoder lives.

## Protocol Driver Abstraction

- Added `src/protocol/driver.ts` with a `KeyboardProtocolDriver` interface implemented by `bytetechDriver` and `xsydDriver`, plus `getProtocolDriver`, `getActiveConnectedDriver`, `isAnyProtocolConnected`, `disconnectAllProtocols`, and `autoConnectAnyProtocol`.
- `useDeviceSyncController.ts` now routes connect, hydrate, profile-slot read, and disconnect through the driver layer.

## Frontend Component Split

- `AdvancedKeysPage.tsx` slimmed by extracting `advanced-keys/` (`DksGrid`, `ActionPicker`, `OutputTester`, `DksUnsupportedModal`).
- Further extraction into `custom-rgb/`, `macro/`, and `rgb/` modules.
- New `useSlotHistory` hook with per-slot undo/redo, burst commits, and slot isolation.

## Native HID Helpers

- Extracted `hid_device_catalog.h`, `hid_packet_policy.h`, and `hid_ipc_router.h` out of `hid_bridge.cpp`:
  - Raw-input device filtering and VID/PID catalogs.
  - Packet validation and the command allowlist for ByteTech and XSYD.
  - IPC line queue and waitable-timer deadline computation.

## Fixes

- **XSYD Slot 3 overflow**: `computeProfileHallSignature` referenced a key table that was no longer imported, which broke auto-switch warm-up on WIN 68 HE MAX. The signature is now derived from the target board's key list.
- **RGB hydration check**: an operator-precedence bug (`!x === 'xsyd'`) in `useDeviceSyncController.ts` made the guard always false.
- **Service RGB persistence**: shutdown now calls `rgbController.stop({ persist: false })`, and custom/rhythm RGB is re-applied on start when the service comes up offline.
