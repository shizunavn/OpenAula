# OpenAula v1.4.1

WIN 68 HE MAX Rhythm Sync Native USB Write Fix & Unthrottled Web Worker.

## Native Service USB Streaming Fix

- Resolved "Device disconnected or RGB write failed" on WIN 68 HE MAX:
  - Corrected `writeReport` in `service/native/hid_bridge.cpp` to validate against `rhythm::xsydMagic` (`0x5C`) rather than rejecting all XSYD writes unconditionally.
  - Added proper USB Report ID offset calculation (`reportOffset = device->output > 64 ? 1 : 0`) when sending 64-byte XSYD lighting packets to Windows HID collections.
  - Added `HidD_FlushQueue` after packet delivery to ensure immediate transmission without pipeline buffering.
- Transcoded Custom RGB batches in the native service:
  - Added `decodeCustomBatch` to `service/native/rhythm_core.h` to convert HERO68-format queued custom batches into 68-key frames.
  - Encoded and streamed custom frames to WIN 68 HE MAX via `encodeXsyd` (`0x18` mode `0x15` + 5 × `0x2A` batches).

## Unthrottled Web Worker Timer

- Replaced window `setInterval` with a dedicated Web Worker timer (`startUnthrottledInterval`) in `serviceLighting.ts`.
- Ensures RGB effects, Custom RGB, and Rhythm Sync continue running at full 30–60 FPS even when the browser tab is hidden or minimized.

## Robust Dual-Mode Handover

- In `RhythmSyncEditor.tsx`, eliminated duplicate USB writes between WebHID and native service.
- When the Windows service is running, it owns the native USB streaming pipe. If the service is offline or reports a write failure, the web app automatically falls back to WebHID direct streaming.
